# 08 开发路线图

> 以"人周"计（1 人全职），不含日历承诺。每个里程碑有硬性验收标准，达标才进下一个。顺序安排的逻辑：**先把"不靠 AI 也可靠"的底座（数据+提醒+打卡）打牢，再叠 AI 能力**——提醒失败是致命的，AI 失败只是降级。

## M0 骨架与地基（约 1~1.5 周）

**目标**：可运行的空壳 + 全部技术风险点打通。

- 项目清理（移除计数器示例）、目录结构按 04 文档落地；
- Riverpod + go_router + 主题（含三档字号）+ 四 Tab 空页；
- Drift 接入，建全部表（05 文档），迁移机制跑通；
- `AIClient`：OpenAI 兼容请求打通（拿任意真实 key 手动验证一次）；
- `flutter_local_notifications` 精确闹钟在真机上验证到点触发（含 Android 12+ 权限申请流）；
- CI（analyze + test）。

**验收**：真机安装后四 Tab 可导航；手动写一条测试数据能在到点弹出通知；一个最小 demo 调通真实模型返回文本。

## M1 MVP——可靠的单机用药管理 + 基础 AI 问答（约 3~4 周）

**目标**：不含拍照与语音，产品已可给老人用。

- 药品/计划 CRUD（手动、分步表单）；
- DoseService 任务展开（daily/weekdays/interval_days/as_needed）+ 状态机 + 打卡/撤销/补记；
- 完整提醒链路：每日展开、到点全屏提醒+TTS、升级提醒、漏服判定、重启/启动补偿；
- 模型管理页（增删改查、能力标注、连通性测试、密钥入库 secure storage）；
- AI 助手：系统 Prompt + 工具集（读全量 7 个 + 写 2 个）+ 降级链（03 §5）；
- 今日页、药箱页、助手页、设置页按 07 文档到位；
- 首次启动引导（可跳过模型）。

**验收**：
1. 断网状态下：提醒、打卡、历史查询全部正常；
2. 真机连续 3 天、每天多次：无漏提醒、无状态错乱；
3. "今天吃没吃药""下一个吃什么""帮我记上吃过降压药了"在支持函数调用的模型上全对；在不支持函数调用的模型上走降级仍可用；
4. 杀掉 App 进程后到点提醒照常。

## M2 AI 增强——拍照识别 + 语音交互（约 3~4 周）

**目标**：补齐"AI 驱动"的招牌能力。

- 拍照识别：图片压缩 → 视觉模型结构化抽取 → JSON 校验与重试 → 草稿确认页 → 建卡+预填计划；
- 语音：按住说话（STT，松手等待最终识别并自动发送，失败可编辑）+ TTS 播报回答；助手页与首页入口；
- AI 代办打卡的"可撤销确认条"交互；
- Prompt 迭代：真实老人语料测试（错别字、方言式表达、跳脱话题）。

**验收**：
1. 5 种常见药盒照片（不同光线/角度）识别，字段正确率人工评估 ≥ 80%，存疑字段正确标黄；
2. 全程不动键盘：语音问"今天吃了吗"并语音回答，链路可用；
3. 拍照/建药草稿不确认绝不生效；语音提问松手自动发送，明确的打卡工具成功后可撤销。

## M3 打磨与固化（约 2~3 周）

**目标**：从"能演示"到"敢给父母装"。

- 统计页（日历热图、依从率、漏服清单）+ AI 周报文字导出/分享；
- 数据导出/导入备份；
- 厂商 ROM 引导页（小米/华为/OPPO/vivo 图文）+ 设置页"提醒测试"；
- 适老化全量走查（07 §3 逐条验收）+ 真机矩阵（至少：1 台小米或华为、1 台原生 Android、1 台 iOS）；
- 免责声明、隐私说明页；
- 稳定性：崩溃上报本地日志导出（无第三方 SDK）。

**验收**：交给 2~3 位真实老人/子女试用 1 周，回访修正 Top 问题后定 v1.0。

## M4 之后（候选池，不承诺）

按需评估：多语言、药品库存与缺药提醒、可穿戴/小组件、家属远程查看（届时再议用户系统）、本地小模型（Ollama/LM Studio 深度适配）、云端 ASR/TTS 备选、国内药品条码数据库授权与覆盖扩展。

条码扫药已接入免费 openFDA，支持扫码/输入条码、核对、填写并保存，无 AI 也能使用；主要覆盖美国市场，国内药品查不到时转拍照或手动。实现与服务限制见 [11 药品条码查询](11-药品条码查询.md)。

## 里程碑依赖与风险提示

- M1 的提醒链路是全项目最硬的骨头（各 ROM 差异），预留了缓冲；若 M1 超期，砍 AI 代办（写工具），**不砍提醒补偿机制**；
- M2 依赖用户有视觉模型可用性，若目标用户普遍无 vision key，拍照功能在 UI 上保持隐藏即可，不影响发布。
