## 5. 真机复测步骤与通过标准

1. 用测试药建立同名药、每天多次、昨天/今天的任务。询问/补记时区分计划日期时刻与实际服药时间；候选不唯一必须澄清且零写入。
2. 连续对话超过 20 条，加入指代和纠正，退出页面与重启后续聊。检查当前输入不重复、顺序一致、长会话请求受预算限制。
3. 分别普通陈述、明确记住、更正、删除和撤销。普通陈述不创建记忆；清空聊天保留记忆；删除后不从旧摘要恢复事实。记忆不能改变服药业务记录。
4. 工具成功后断开网络，确认操作条、今日状态和撤销仍在；重新请求不能再次写入。任务随后被其他操作修改时撤销必须提示冲突。草稿重启后可核对但未经确认不生效。
5. 覆盖短按、上滑、60 秒上限、权限申请中松手、识别提前结束/延迟最终回调/无最终回调/无声/网络错误。每次有效松手只发送一次；错误文本可编辑，不能静默发送。
6. 语音问题开启/关闭 TTS；文字问题不新增自动播报。提醒两遍必须前一遍结束后再开始；助手按下录音先停止自己的声音，录音中不能收进助手播报。
7. 录音/识别/请求/播报各状态切 Tab、打开覆盖页、切后台、触发提醒。未发送录音取消；已发请求可保存结果但无迟到播报。清空后无旧消息/摘要回写。
8. 导出/恢复 v2 记忆；导入 v1 保留本机记忆；缺少 v2 memories 或字段损坏要拒绝，既有数据不变化。恢复后旧聊天可见，旧摘要/工具撤销不参与新业务状态。

最终发布门槛：自动化通过并补齐以上真实设备记录。系统 ASR/TTS 可用性不能由模拟回调测试替代。

## 6. Release 开屏停滞修复（2026-10-07）

realme 用户反馈 Release 一直停在原生应用图标。旧 APK 在 Android 17 / API 37
模拟器上强制停止后冷启动，同样停留在开屏，`am start -W` 约 30 秒后超时。
旧 APK 资源表缺失 `drawable/ic_notification` 和 `raw/alert_long`，压缩报告也将它们
标记为不可达；通知初始化在 `runApp` 前按名查找图标，异常会阻止 Flutter 首帧。

修复显式保留资源，并将通知与后台维护移至首帧之后独立执行，添加超时与异常处理。
前台共用通知网关，并发初始化共享 Future，失败/超时后可重试。

验证结果：

- 静态分析与分层检查通过，全部 230 项测试通过，其中新增 11 项覆盖平台异常/超时、
  页面仍可操作、冷启动提醒路由、迟到结果丢弃、并发初始化与重试、iOS 显式权限申请。
- Debug / Release APK 均构建成功；Release 合并清单与最终 APK 通知资源检查通过。
  新检查能拒绝旧 APK，确认两项通知文件资源缺失。
- 在现有模拟器上覆盖安装 Release，保留数据；强制停止后普通冷启动约 3 秒进入今日页。
  设置中的提醒测试成功发出通知，系统记录的小图标资源为 `ic_notification`，
  提醒渠道的声音 URI 为 `android.resource://com.carepill.app/raw/alert_long`，音频用途为 alarm。
- 点击实际测试通知返回今日页（其 payload 没有药品任务）；另以带任务 ID 的通知启动意图
  强制停止后冷启动，约 2.7 秒进入全屏提醒页。模拟 ID 不创建药品或打卡数据。
- 模拟器以无音频模式运行，未声学验收铃声；realme 实机未连接，需覆盖安装新包复测。
  iOS 权限行为有模拟平台测试，实际启动/弹窗仍需 macOS / iOS 环境验证。
