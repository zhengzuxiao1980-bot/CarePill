# 药品条码查询

## 数据源调研（2026-10-07）

已接入 **openFDA Drug Label API** 的 `openfda.upc` 精确查询。它免费、可不带密钥调用，主要覆盖美国市场人用药品，部分标签没有 UPC 字段。不能承诺中国药盒覆盖率，也不能用于批准状态、真伪鉴定或用药决策。

| 数据源 | 已核实情况 | 本次选择 |
| --- | --- | --- |
| [openFDA 药品标签](https://open.fda.gov/apis/drug/label/) | 有 UPC 字段，匿名真实请求成功；药品资料在 [许可说明](https://open.fda.gov/license/) 中原则上为公有领域 / CC0（仍受服务条款约束） | 接入 |
| [聚合数据商品条码](https://www.juhe.cn/docs/api/id/52) | 通用商品资料，需申请 Key，页面有试用、充值购买流程；不能确认是长期免费药品数据库 | 不内置账户或试用密钥 |
| [码上放心](https://www.mashangfangxin.com/) | 支持原中国药品电子监管码；公众网站查询带验证码，企业接口需要平台接入 | 不绕过验证码、不抓取私有接口 |
| [极速数据条码生成识别](https://www.jisuapi.com/api/barcode/) | 解码/生成条形码，页面提供有限试用；不是药品身份数据库 | 本地扫码解码无需该服务 |

没有找到能确认长期免费、公开允许直接接入且覆盖国内药品的通用条码查询 API。保留 `BarcodeLookup` 接口以便未来接入获得授权的数据源；未引入付费服务或需要用户账户的依赖。

[openFDA 配额说明](https://open.fda.gov/apis/authentication/)：无 Key 每 IP 每分钟 240 次、每天 1,000 次；免费 Key 每分钟 240 次、每天 120,000 次。文档开头建议 Key，但同时明确列出匿名限额，匿名调用已实测。当前应用直接匿名请求，不内置共享 Key。多个设备共用出口 IP 时共享额度；429 显示稍后重试。规则和数据覆盖可能变化。

## 使用流程

- 药箱空态按钮、加药菜单、首次引导均提供「扫条码添加」，无需 AI 配置。
- 页面先告知数据源、覆盖范围与发送内容，再打开相机或输入数字查询。
- Android 使用 `mobile_scanner` 的 **bundled ML Kit**，无需首次下载模型或 Google Play Services；iOS 使用系统识别能力。相机画面不上传。
- ML Kit 会产生 SDK 使用与性能诊断事件（模拟器日志可见 `FIREBASE_ML_SDK` / DataTransport），因此不承诺整个扫码组件绝无遥测；关于页已说明。商店发布前需按 [ML Kit 条款](https://developers.google.com/ml-kit/terms) 和当前 SDK 披露填写数据安全信息。
- 支持 EAN-8 / EAN-13 / UPC-A / UPC-E（扫描器报告后展开为 UPC-A）/ GTIN-14、GS1 AI `(01)` 的 DataMatrix / QR / Code 128，以及带 `/01/<GTIN>` 的 HTTPS GS1 Digital Link。
- 普通网址二维码不自动打开，不请求其中的 URL。20 位中国药品追溯码单独提示不支持，不发往 openFDA。GS1 仅提取 GTIN，批号、效期、序列号不上传。
- GTIN 校验位检查通过后，只向固定 `https://api.fda.gov/drug/label.json` 发送商品编号的等价补零形式；不做 NDC 猜测或模糊药名匹配。
- 最多取 20 条标签记录，二次验证返回 UPC 相等且为人用药，去掉重复版本。可能返回多项，用户对照药盒选择。没有结果不表示药品不存在或无效。
- 显示药名、通用名、厂家和来源；不从可能涵盖多个包装的标签中猜测规格、剂型、剂量或服药时间。
- 选择结果进入现有加药三步表单，预填药名、来源备注；未知剂型为「其他」，计量单位必填、规格留空，默认无定时提醒。填写并最终确认后才写药品和计划。
- 返回查询页保留结果；首次引导中保存完成返回并结束引导。查不到、断网、超时或限流时仍能转手动/已有拍照识别流程。

## 实现与数据

`MedicationBarcode` 管格式和校验，`BarcodeLookup` 是可替换查询接口，`OpenFdaBarcodeLookup` 负责固定端点请求和响应验证，`BarcodeLookupController` 管输入、加载、错误、取消和结果。页面没有查询仓库或写库行为。

重复检测只返回相机结果一次；同一查询处理中不重复提交。修改输入、离开扫码页会取消请求并丢弃迟到的结果。相机路由使用插件拥有的控制器，自动管理前后台和退出时的关闭。

药品来源新增枚举字符串 `barcode`，复用现有 source 字段，备注记录来源、商品编号和厂家，不改数据库字段或备份结构。现有枚举解析和备份按值读写。

## 验证

- `flutter test test/barcode_lookup_test.dart`：格式、校验位、UPC-E、GS1、二维码、追溯码、HTTP 查询参数、非人用药过滤、重复标签、空结果、限流、超时、离线、取消、旧响应、离开页面。
- `flutter test test/i18n_widget_test.dart --plain-name Barcode`：中英文、360/390 宽度、特大字号 + 1.3 倍系统文字、键盘、查询及核对前不写库、取消返回、单位校验、扫码来源、无默认提醒、首次引导与手动回退。
- 可重复真实查询：`dart run tools/check_barcode_lookup.dart 0300450297211`。这是 openFDA 实际记录的商品条码，验证返回 TYLENOL / ACETAMINOPHEN / Kenvue Brands LLC；仅作接口示例，不构成用药建议。联网检查与 CI 假客户端测试分开。
- Windows 环境可构建和检查 Android；iOS 配置已补齐相机权限文案，真实相机扫码与启动需在 macOS/iOS 环境验收。
- Android API 37 模拟器：相机权限与实时预览已检查；使用实际 ML Kit 本地组件分别解码 EAN-13 图片和 GS1 Digital Link QR 图片，均得到 GTIN `00300450297211`。真实药盒在不同光线、镜头下的扫码仍需真机补验。
- 同一模拟器中的应用真实联网查询 `0300450297211` 成功，返回 TYLENOL 的药名、通用名及厂家；点击核对进入表单，返回仍保留输入与结果，未保存测试药品。
- 最终验证：静态分析零问题，分层检查通过，完整 219 项测试通过，Android Debug / Release 构建及合并清单检查通过；Release 包已安装到现有模拟器。
