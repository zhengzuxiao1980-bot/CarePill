# 03 AI 能力与模型接入设计

> 本文档是所有 AI 相关功能（对话、识别、播报、代办）的实现依据。

## 1. 设计总则

1. **自带模型（BYO Model）**：App 不内置任何模型服务。用户在"设置 → AI 模型"中添加一个或多个 **OpenAI 兼容** 接口（`base_url` + `api_key` + `model`），这是覆盖面最广的方案：DeepSeek、通义（DashScope 兼容模式）、Kimi、智谱、OpenRouter、Together、本地 Ollama / LM Studio 全都适用。
2. **能力声明**：每个模型配置要标注它支持的能力（对话 / 视觉 / 函数调用），AI 功能运行前检查当前模型是否具备所需能力，不具备则引导切换或降级，绝不硬报错。
3. **降级链**：函数调用 → 提示词 JSON 协议 → 规则意图匹配（见第 5 节）。任何一级可用，AI 助手就不会完全瘫痪。
4. **直连**：AI 请求由 App 直接发往用户配置的地址，不经过任何自建中间服务器。

## 2. 模型配置（AIModelConfig）

### 配置引导（2026-10-07）

新增和编辑统一为四步：选择供应商 → 连接供应商 → 选择模型 → 测试并完成。
常用供应商展示 DeepSeek、通义千问、Kimi、智谱、OpenRouter；Ollama 与自定义
OpenAI 兼容服务放在“其他方式”。供应商与模型预设集中在 `AiProviderPreset`，
密钥申请链接使用系统浏览器打开，失败时可以复制地址。未知模型默认只启用聊天。

草稿由 `ModelSetupController` 管理，测试发送不含用药数据的最小请求，不先写入数据库。
测试失败或未测试均可选择“先保存，稍后测试”；保存成功不代表连接成功。测试状态只在
当前应用会话内显示，重启后可重新测试。普通连接测试不验证图片识别能力。

编辑时按完整接口地址识别供应商，未知地址保持自定义；保留名称、ID、创建时间、
temperature 和未修改参数。密钥只在控制器内存与安全存储中，页面不回填已保存的密钥。
更换供应商或接口地址会清除草稿凭据并要求重新输入，不会发送原密钥到新地址。
测试期间禁止重复提交，返回上一步或关闭页面会取消请求，过期结果不更新界面。

Ollama 自动使用兼容接口的占位凭据 `ollama`，不要求用户申请密钥。手机连接电脑需要
电脑局域网地址和服务端的访问许可。Android 允许用户配置的 HTTP 服务，预设云服务
仍使用 HTTPS；iOS 声明本地网络用途和 `NSAllowsLocalNetworking`。未关闭 TLS 证书校验。
不新增配置数据库字段，不改变备份结构。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | uuid | |
| 名称 | string | 用户可读，如"女儿的 DeepSeek" |
| baseUrl | string | 如 `https://api.deepseek.com`（路径按服务商要求填写） |
| apiKey | string | 存 `flutter_secure_storage`，**绝不入库明文、绝不导出默认包含** |
| modelId | string | 如 `deepseek-flash` 或 `deepseek-v4-pro` |
| 能力-对话 | bool | 默认 true |
| 能力-视觉 | bool | 用户勾选；用于决定拍照识别入口是否可用此模型 |
| 能力-函数调用 | bool | 用户勾选；仅服务明确表示不支持工具协议时降级 |
| temperature / maxTokens | num/int | 可选高级项；maxTokens 未设置时对话输出上限 512 tokens |
| contextWindowTokens | int | 上下文窗口，默认 8,192 tokens；另预留 1,024 tokens 余量 |
| 用途 | enum | `chat` / `vision`（允许同一配置承担多用途） |

**连通性测试**：保存前发送一个极小 chat 请求（"ping"，max_tokens=1）验证地址、密钥、模型名三要素；视觉能力可选用一张 1px 测试图验证。

**多配置规则**：至少一个配置标记为"对话默认"；拍照识别优先用标记了 `vision` 的配置，没有则复用对话默认并在识别前提示"当前模型可能不支持看图"。

**DeepSeek 预设（2026-10-07 核对）**：接口地址为 `https://api.deepseek.com`；`deepseek-flash` 支持对话、视觉及工具调用，`deepseek-v4-pro` 支持对话及工具调用、不支持视觉。密钥从 `https://platform.deepseek.com/api_keys` 申请。已退役的 `deepseek-chat` / `deepseek-reasoner` 配置在编辑页提供更新入口，保留名称和密钥，保存后生效。当前模型默认开启思考模式；应用为短回复、图片提取和工具调用显式发送 `thinking: {type: disabled}`，避免短输出额度耗在推理上及工具续轮缺少 `reasoning_content`。该参数仅用于官方 DeepSeek 接口的已知模型，其他 OpenAI 兼容服务不受影响。

官方依据：[模型与价格](https://api-docs.deepseek.com/quick_start/pricing)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode)、[图像输入](https://api-docs.deepseek.com/guides/vision)。

## 3. 能力矩阵 → 功能可用性

| 功能 | 需要能力 | 无可用模型/能力时的表现 |
| --- | --- | --- |
| AI 助手问答 | 对话 | 入口显示引导页；手动管理不受影响 |
| 助手代办打卡 | 对话 + 函数调用（或降级） | 降级方案仍可用；再不行提示去首页手动打卡 |
| 拍照识别建卡 | 视觉 | 隐藏拍照入口，仅手动添加 |
| 提醒 TTS 播报 | 本地 TTS（系统） | 纯铃声通知，不受模型影响 |
| 语音提问 | 系统 STT + 对话 | 显示具体不可用原因、系统设置入口；仍可键盘输入 |

> TTS/STT 默认走系统能力（`flutter_tts` / `speech_to_text`），不调用用户配置的大模型语音接口。系统引擎可能使用网络，离线可用性取决于系统服务、语言包和设备；不能承诺离线、零延迟或所有 ROM 可用。

## 4. Function Calling 工具集（AI 助手的核心）

助手 = 系统 Prompt + 对话模型 + 以下本地工具。AI 只能通过工具读写数据，**不存在"AI 自己编造用药情况"的通道**。

| 工具 | 类型 | 说明 |
| --- | --- | --- |
| `get_today_plan()` | 读 | 返回今天全部服药任务（task_id、药名、时刻、剂量、状态） |
| `get_dose_status(date?)` | 读 | 按日期查询打卡情况，缺省今天。回答"我今天吃没吃药"的主力 |
| `get_next_dose()` | 读 | 最近一次待服任务（含口语化时间） |
| `list_medications()` | 读 | 在用药品清单及计划摘要 |
| `get_medication_detail(name)` | 读 | 单药详情：规格、频次、备注、说明书字段；支持名称模糊匹配 |
| `get_adherence_stats(days)` | 读 | 近 N 天依从率、漏服清单 |
| `mark_dose_taken({task_id \| medication_name, scheduled_date?, scheduled_time?, when?, note?})` | 写 | 打卡（支持补记）。**仅允许改当天与昨天**；优先传 task_id（从查询工具结果原样取），无 task_id 时必须唯一匹配药品及今天/昨天的待服任务；存在多候选时先澄清。scheduled_date/time 表示计划时刻，when 仅表示实际服药时间 |
| `skip_dose({task_id, reason?})` | 写 | 标记跳过 |
| `create_medication_draft(draft)` | 写 | 对话中生成**草稿**，入草稿箱待用户确认，不直接生效 |

> 工具参数以 `task_id`（dose_tasks 主键）为准——任务才是"某天某次"的实例；
> `schedule_id` 只用于溯源，不作为写工具入参（实现以 `lib/ai/tools/tool_registry.dart` 为准）。

**执行环（Agent Loop）**：用户消息按轮次立即持久化 → 构建预算内上下文 → 请求模型 → 校验并执行工具 → 持久化工具调用和结果 → 继续请求。每次执行最多 5 次模型调用（含摘要、降级和润色）、10 次工具执行；达到上限后使用已完成操作给出确定反馈。查询工具超时 10 秒；写入在共享数据库事务中完成，不使用“超时返回但后台继续写”的包装。

每次写入与操作收据、撤销快照同事务提交；按轮次、工具、原始参数及规范化目标去重。成功后立即显示操作条、刷新今日页并同步提醒。模型续答/提醒同步失败不能掩盖已提交事实。重试沿用原轮次和原用户消息，通过持久化收据恢复，不重复执行写入。撤销前比较当前状态与操作后的快照，不覆盖后续修改。

**写操作安全**：`mark_dose_taken` 等写工具执行结果立即写入 UI 并提供撤销；AI 无法删除药品、修改剂量与计划（没有暴露这些危险工具，计划变更必须走表单）。

## 5. 降级方案（模型不支持函数调用时）

已按以下三级实现（`AgentService.handleUserInput`）：

- **一级降级：提示词 JSON 协议**。未勾选"支持函数调用"时直接走此模式：系统 Prompt 附工具清单，要求模型把"想调用的工具+参数"以 `{"tool": "...", "args": {...}}` JSON 输出，本地解析后按相同逻辑执行，结果以 `[工具结果]` 用户消息回传。勾选了函数调用且服务端明确返回“不支持 tools/function calling”时才降级。鉴权、限流、网络、普通协议错误分别报告。
- **二级降级：规则意图匹配**。JSON 协议模式下模型连续输出无法解析的内容时，放弃模型输出，本地意图识别（"吃没吃/吃了没"→ `get_dose_status`；"下一个/接下来"→ `get_next_dose`；"记一下/吃过了/帮我记上"→ `mark_dose_taken`，含药名与"8 点"式时间解析），仅本轮没有执行工具或提交写入、且未达到模型调用上限时尝试规则；规则与模型共用执行器。失败/歧义不能生成成功文案，润色失败保留真实工具结果。
- 用户在模型配置里勾选"支持函数调用"即可跳过降级开销。

## 6. 拍照识别流程（视觉）

```
拍照/选图 → 压缩与方向纠正 → 视觉模型（结构化抽取 Prompt）→ JSON 解析与校验
   → 草稿确认页（大字段逐项可改，原图对照）→ 用户点"没问题" → 建卡 + 预填计划草稿
```

- **抽取目标字段**：药品名、剂型、规格、单位、用法用量原文、每次剂量、每日次数与时刻、餐前餐后、有效期、注意事项原文。
- **输出契约**：要求模型仅输出 JSON（附 schema 与一个完整示例），本地 `jsonDecode` + 字段级校验（时刻格式 HH:mm、剂量为正数等），解析失败重试 1 次（附上错误信息），仍失败则提示手动录入。
- **幻觉防护（重要）**：
  1. 照片模糊或拍不到关键信息时，要求模型输出 `"not_readable": true` 而不是猜；
  2. 抽取出的"用法用量原文"必须原样保留并展示在确认页，老人/子女可对照原图核对；
  3. 一切识别结果只是草稿，确认页是强制步骤，不可跳过；
  4. 置信存疑字段（模型标 `uncertain` 的）在确认页高亮提示"请核对"。
- 多张照片（药盒正面+说明书）支持追加识别做字段合并（P2，先做单图）。

## 7. Prompt 策略

**系统 Prompt 框架**（分段维护在代码常量中，便于迭代）：

1. **角色**："你是老人用药助手 CarePill，说话像耐心的家人，用语简单、具体、温暖。"
2. **适老化表达规则**：短句；一次只说一件事；药名用用户录入的名字；时间说"早上 8 点"不说"08:00"；先给结论再给细节；不使用医学术语，必要术语立刻解释。
3. **事实边界**：用药状态必须来自工具结果，禁止推测；查不到就说查不到。
4. **安全边界**（详见第 8 节）。
5. **工具使用说明**（含降级 JSON 协议时替换为此段）。
6. **上下文注入**：当前日期时间、今天任务摘要（低 token 成本地预置，减少一轮工具调用）。

**少样本**：为高频场景（查状态、补打卡、拒答医疗建议）各内置一组示例对话，随系统 Prompt 下发。

**回答长度**：默认要求"三句话以内"，TTS 场景更重要。

## 8. 安全护栏（医疗安全红线）

| 场景 | 行为 |
| --- | --- |
| 问剂量调整 / 换药 / 停药 | 明确拒绝 +"请问医生或药师"，并可协助查看当前医嘱记录 |
| 描述胸痛、呼吸困难、跌倒等急症 | 立即建议就医/拨打 120，展示紧急联系人卡片（P2） |
| 问药品相互作用 | 不判断，引导咨询药师；可复述两药的说明书注意事项原文 |
| 识别/提取的用法用量 | 永远是草稿，必须人工确认 |
| AI 一切回答 | 界面固定脚注："AI 回答仅供参考，用药请遵医嘱" |

## 9. 语音（STT/TTS）

- `VoiceController` 在应用层维护空闲、准备录音、录音、等待最终结果、发送中、播报中状态。按下停止助手播报；松开停止采集，等待最终结果并自动发送一次，不弹发送确认框。中间识别文本实时展示，发送后的用户消息保留。
- 按住不足 300 ms 丢弃；向上移动 64 逻辑像素标记取消；最长录音 60 秒，到限停止采集，仍等松手才发送。系统提前结束单段时按段合并，最终文本和 done 事件协调后继续下一段。
- 停止后最多等 2 秒最终结果，正常停止缺失最终回调时可用最近非空文本。权限/网络/引擎错误保留文本供编辑，不自动发送。权限对话框返回时手势已结束则不启动录音。
- 初始化过程缓存；区分无服务、拒绝权限、语言缺失、无声音和识别错误，提供重试、文字输入及系统设置入口。
- 语音发送成功后自动播报（服从 TTS 开关）；文字发送不新增自动播报。TTS 检查语言支持、返回值和错误事件，等待真实完成或取消事件。提醒第二遍等第一遍完成。
- 录音/播报互斥，提醒优先。Tab、覆盖页面、后台切换释放助手音频；页面保留在 indexedStack 中也生效。隐藏期间网络可完成并保存，迟到回答不会自动播报，回来不补播。
- Android 蓝牙权限按插件的系统版本逻辑申请，拒绝蓝牙只禁用蓝牙路由，仍可使用手机麦克风；这一行为还须真机验证。iOS 更新权限说明并维持识别/播报音频会话切换。

## 10. 隐私与密钥安全

- API Key 只存 `flutter_secure_storage`（Android Keystore / iOS Keychain）；导出备份默认剥离，单独导出需二次确认。
- 发往模型服务的内容 = 对话文本、相关显式记忆、滚动摘要和实时任务摘要（对话请求），或用户主动拍摄的照片（视觉请求）；除此之外不收集、不上报任何数据。
- 设置页明示："AI 回答由你自己添加的模型服务生成，处理过程受该服务商隐私政策约束。"
- 对话历史仅存本地，可一键清空。

## 11. 持久上下文与显式长期记忆

请求顺序为系统规则、当前时间及业务摘要、用户自述记忆、历史摘要、最近完整轮次、当前输入。历史数据不能覆盖规则或实时业务事实。当前输入按 ID 排除，历史按稳定递增序号排序；失败/取消轮次不作为已完成历史回放。

`ConversationContext` 使用可替换的保守估算器，计算消息、工具 schema、调用及结果。每轮请求重新检查预算；优先丢弃最旧的完整轮次，超大工具结果保留 JSON、配对 ID、总数及明确截断/查询标记。当前用户输入过长时保留原文并报错，不能静默剪短。服务商上下文超限仅重裁一次，已提交工具不会重放。

历史移出窗口前尝试滚动摘要：目标 768 tokens，无工具，10 秒超时，保存覆盖到的用户消息序号。摘要保留指代、纠正、待解决事项；服药历史不能变成当前事实。失败不推进游标，随后重试；查询仍使用预算内完整最近轮次。

长期记忆仅由明确“记住/更正/遗忘”要求或记忆管理页产生。工具为 `save_memory(content,id?)`（同一事实更正沿用 id）、`search_memories(query?)`、`forget_memory(id)`；写工具绑定来源用户消息，内容须来自原话，不能从普通聊天、助手或工具结果自动归纳用户画像。目标有歧义时澄清。保存/更新显示具体内容并可撤销，管理页支持列表、编辑、单条/全部删除。

每轮用中文词组和英文词匹配检索，按相关性、更新时间排序，注入上限 1,024 tokens。记忆修改/删除使摘要失效并抑制撤回来源的历史轮次；模型响应若基于旧记忆版本则丢弃后重新请求。记忆永不直接修改药品、剂量、计划或服药状态。

清空聊天取消在途请求、递增会话版本并删除聊天/摘要；保留长期记忆及已提交业务操作。迟到回复/摘要不能重新写入。完整数据契约见 05 文档，验证状态见 10 文档。
