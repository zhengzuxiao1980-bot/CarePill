# 09 风险与开放问题

## 1. 风险清单

| # | 风险 | 影响 | 概率 | 缓解措施 |
| --- | --- | --- | --- | --- |
| R1 | **AI 幻觉**：识别错剂量/用法，老人照做 | 高（健康安全） | 中 | 识别结果仅草稿+强制确认页+原图对照+存疑高亮（03 §6）；AI 不暴露改计划/剂量的工具 |
| R2 | **医疗边界**：AI 给出超出能力的建议 | 高 | 中 | 系统 Prompt 硬边界 + 固定免责脚注 + 急症引导就医（03 §8）；拒绝类回答列入测试用例 |
| R3 | **国产 ROM 杀后台**：提醒不到点响 | 高（核心承诺失效） | 高 | 四重补偿触发源（06 §1）+ 厂商引导页 + 提醒测试入口；M1 优先攻此关 |
| R4 | 老人不会配模型 | 中（AI 全废） | 高 | 引导分厂商示例卡；子女配置一次即可；无模型时产品仍完整可用（产品定位即如此） |
| R5 | 老人打字/操作困难，功能用不起来 | 高 | 中 | 语音优先 + 快捷 chip + 适老化规范硬验收（07 §3）；M3 真实老人试用 |
| R6 | API 成本/限流（用户自己的 key） | 低 | 中 | 上下文摘要精简注入、max_tokens 限制、失败重试有上限、TTS/STT 走系统零成本 |
| R7 | 模型响应慢/不稳定，老人以为坏了 | 中 | 中 | 流式输出（P1）、超过 3 秒先播"我想想哈"、降级链保证基础问答可用 |
| R8 | 密钥泄露 | 中 | 低 | secure storage、导出默认剥离、请求直连不经中间服务器（03 §10） |
| R9 | 单设备数据丢失（换机/摔机） | 中 | 中 | M3 提供导出/导入；换机引导文案；云同步留待用户系统版本 |
| R10 | 范围蔓延：功能越做越多，核心不稳 | 高 | 高（个人项目常见） | 02 文档优先级表是唯一范围依据；每个里程碑验收达标才前进；M4 候选池只进不做 |

| # | 问题 | 建议 | 需要决定的时间 |
| --- | --- | --- | --- |
| Q1 | **首发平台**：Android 优先还是双端同步？老人群体 Android 占比高、ROM 适配工作量大 | 建议 Android 先行，iOS 跟进 M3 | M0 开始前 |
| Q2 | ~~计划建模：一药多时刻用"单计划多时刻"还是"多计划单时刻"（05 §2 的二选一）~~ **已拍板：单计划多时刻**，见 ADR-001 | 按建议落地 | ✅ M1 动工前 |

| Q6 | 应用分发方式：侧载 APK / 应用商店（商店对医疗类目与隐私合规有要求） | 建议先侧载给种子用户，商店合规在 M3 后评估 | M3 |

## 3. 假设与依赖（文档成立的前提）

- 用户能获得至少一个 OpenAI 兼容模型的访问权限（自己或子女代办）；
- 老人手机为本人随身携带（提醒到人而不是到药盒——智能药盒硬件不在范围内）；
- v1 单用户单设备：一台设备 = 一位老人的用药数据（多老人共存需求出现时再建模"档案"概念）。
