# 07 界面与交互设计

扫码添加补充：药箱空态、加药菜单和首次引导提供「扫条码添加」，不依赖 AI 配置。先说明 openFDA 覆盖范围与条码联网查询，再扫描或输入；结果需对照药盒核对并完成现有表单。没有结果和网络错误均可转拍照/手动，追溯码不支持时明确提示。完整行为见 [11 药品条码查询](11-药品条码查询.md)。

## 1. 信息架构：四个 Tab，没有更多

```
┌────────────────────────────────────┐
│                                    │
│   今日        药箱       AI助手  设置 │   ← 底部导航(图标+大字标签)
│                                    │
└────────────────────────────────────┘
```

| Tab | 回答的问题 | 内容 |
| --- | --- | --- |
| **今日**（默认） | "现在该干什么？" | 今天的时间轴：已吃✓ / 待吃（大卡片，到点变成超大"吃了"按钮）/ 漏吃红标；顶部"下一顿：晚上 8 点降压药" |
| **药箱** | "我在吃哪些药？" | 在用药卡列表（名称+下次时间+剂量），点开编辑；右下角大号"＋加药"（手动/拍照二选一） |
| **AI 助手** | "我有问题想问" | 对话流 + 常驻麦克风大按钮 + 常用问题快捷chip（"今天吃了吗""下一顿吃什么"） |
| **设置** | 子女的领域 | 字体、提醒、语音、AI 模型管理、数据备份、关于与免责 |

全局元素：任意页面顶部右上角固定"字"按钮 → 三档字号切换（老人最常见的即时需求）。

## 2. 页面清单

### 品牌资源与 AI 分步配置（2026-10-07）

- 品牌原图为根目录 `icon.png`。执行 `dart run tools/generate_brand_assets.dart`
  更新 Android/iOS 安装图标、原生开屏和应用内品牌资源；桌面/Web 安装图标不变。
- 开屏为 `#F6FBFF` 背景配居中图标，随 Flutter 首帧结束，不添加固定倒计时。
  Android 12+ 独立适配安全裁切区，通知使用透明底单色小图标。
- 新增和编辑 AI 配置均一步一屏，显示“第 X 步，共 4 步”，主操作固定在底部。
  系统返回键和顶部返回键优先返回上一步并保留输入，完成后返回原入口。
- 先选择供应商，再提供申请密钥的说明与官网入口；预设填好地址与推荐模型。
  名称、地址、能力、用途、输出预算等放入“高级设置”。
- 最后一步展示连接测试状态及修复建议，始终允许“先保存，稍后测试”。首次引导
  可以跳过配置，保存后进入加药步骤；提示“配置已保存”，不暗示网络已验证。
- 文案提供中英文，按 360/390 宽度、特大字号和系统缩放 1.3 验证可滚动布局及键盘场景。

| 页面 | 关键内容与交互 |
| --- | --- |
| 引导·欢迎 | 一屏一句话："CarePill，帮您记住每次吃药"。开始 → |
| 引导·加模型 | 选择供应商 → 连接供应商 → 选择模型 → 测试并完成；首次使用仍可暂时跳过 |
| 引导·加第一个药 | 手动表单 或 拍照识别，完成即进今日页 |

| 模型管理 | 配置列表+状态（上次测试结果／尚未测试）；新增与编辑共用四步引导；保留"测试一下"按钮 |

## 3. 适老化设计规范（硬性要求，评审按此验收）

| 维度 | 规范 |
| --- | --- |
| 字号 | 正文基准 ≥ 18sp，默认档"大"（正文 20sp），可切特大（正文 24sp）；支持系统字体缩放 |
| 对比度 | WCAG AA 以上；避免浅灰小字；红绿色盲安全：状态不只靠红绿，配图标（✓/！/✗） |
| 点击目标 | ≥ 64×64dp，主要操作（吃了）≥ 96dp 高；间距充足防误触 |
| 布局 | 一屏一件事；每屏一个主操作；不用抽屉/手势/悬浮球等隐性交互 |
| 反馈 | 所有操作有明确反馈（声音/动画/文字）；破坏性操作二次确认；一切可撤销 |
| 输入 | 能选不填、能说不打：时间用滚轮选择器、剂量用 +/− 步进器、频率用模板（每天/隔天/每周几次） |
| 容错 | 表单草稿自动保存；AI 回答错了有"不对"按钮收集纠偏 |
| 语言 | 全部中文口语，见 §5 |

## 4. 关键流程走查

**首次使用（子女视角，5 分钟内完成）**：欢迎 → 跟随四步引导配置 AI（可先保存稍后测试）→ 拍药盒或手动添加 → 核对草稿 → 选"每天 2 次，早 8 点晚 8 点" → 保存 → 设置页点"提醒测试"确认会响 → 交给老人。

**老人日常（目标：每次吃药 2 次点击内）**：到点全屏提醒自动弹出 → 按"吃了" → 完。或没听到提醒 → 打开 App 即是今日页待吃大按钮 → 按"吃了"。

**有问题时**：助手 Tab → 按住麦克风："我今天吃药了没？" → 松开等待识别自动发送 → 听 TTS 回答（遵守开关）。

## 5. 文案原则与示例

原则：像家里晚辈说话；短句；先结论；时间口语化；不用"同步/档案/依从率"等词。

| 场景 | ✅ 推荐 | ❌ 避免 |
| --- | --- | --- |
| 打卡成功 | "记上了！降压药，早上 8 点，1 片。" | "服药记录已提交" |
| 问吃没吃 | "吃过了：早上的降压药 8 点 5 分吃的。中午 12 点的降糖药还没到点。" | "查询到 2 条记录，1 条已完成…" |
| 漏服 | "早上 8 点的降压药好像没吃。想起了就先补上，别一次吃两顿的量。" | "检测到依从性异常" |
| 识别失败 | "照片有点模糊，没看清。麻烦再拍一次，离近一点。" | "OCR 解析错误，code=422" |
| 无模型 | "还差一步：告诉我用哪个 AI。点这里，跟着例子填一下就好。" | "未配置推理服务" |
| 免责脚注 | "AI 说的仅供参考，吃药请听医生的。" | —（脚注常驻但低调） |

## 6. 助手连续对话与记忆管理

- 历史按序号展示，40 条一页向前加载；用户消息立即显示。失败原文保留，可沿原轮次重试，不重复插入消息。
- “已记住的内容”入口提供记忆列表、添加、编辑、单条删除、全部删除。明确标识为用户自述；保存后展示具体内容并可撤销。聊天清空对话框说明保留长期记忆及已提交服药记录。
- 操作条在业务事务成功时出现，不等模型续答；部分失败显示“操作已完成”等确定反馈。所有待确认新草稿有“去核对”入口，重启后从历史收据恢复。冲突撤销提示而不覆盖。
- 录音状态明确显示：准备、录音、等待最终识别、发送、播报。少于 300 ms 不发送；上滑 64 px 松开丢弃；60 秒停止采集后松开才发送。权限申请晚于松手返回不会开始录音。按钮在模型处理时禁用，在播报中允许按住开始下一次输入。
- 正常停止后等待 2 秒最终文本，缺失最终回调可使用最近文本；错误时不自动发送，文字进入编辑框，可重新按住重试或用键盘发送。缺权限/服务/语言包时显示系统设置入口。
- 切 Tab、覆盖页面或进入后台都取消未发送录音并停止助手播报，即使页面未销毁。回来不补播历史回答。文字提问维持原行为，不新增自动 TTS。
